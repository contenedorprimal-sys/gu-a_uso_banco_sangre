WHERE: quedarse con las filas correctas

WHERE evalúa una condición por fila. Solo las filas que devuelven verdadero pasan a la siguiente etapa. Si la condición produce NULL, la fila no pasa: en SQL, NULL no es verdadero ni falso, es ausencia de valor.

-- Unidades disponibles del grupo O+
SELECT codigo_barras, tipo_componente, fecha_vencimiento
FROM unidades_sangre
WHERE estado = 'disponible'
  AND grupo_abo = 'O'
  AND factor_rh = '+'
ORDER BY fecha_vencimiento;

AND, OR y los paréntesis que salvan la consulta

AND tiene más prioridad que OR. Sin paréntesis, una condición puede significar algo distinto de lo que lees.

-- MAL: interpreta (estado = 'disponible' AND grupo = 'O') OR grupo = 'A'
SELECT codigo_barras, grupo_abo, estado
FROM unidades_sangre
WHERE estado = 'disponible' AND grupo_abo = 'O' OR grupo_abo = 'A';

-- BIEN: unidades disponibles que sean O o A
SELECT codigo_barras, grupo_abo, estado
FROM unidades_sangre
WHERE estado = 'disponible'
  AND (grupo_abo = 'O' OR grupo_abo = 'A');

La segunda consulta también se escribe con IN, que suele ser más corta y más clara:

SELECT codigo_barras, grupo_abo, estado
FROM unidades_sangre
WHERE estado = 'disponible'
  AND grupo_abo IN ('O', 'A');

NULL: el valor que no es cero ni cadena vacía

-- Donantes sin correo registrado
SELECT id_donante, nombre, apellido_paterno
FROM donantes
WHERE correo IS NULL;

-- Donaciones sin observaciones
SELECT id_donacion, id_donante, fecha_donacion

NULL = NULL no devuelve verdadero; devuelve NULL. Por eso se usa IS NULL. Y cuidado con NOT IN: si la lista contiene un NULL, el resultado puede quedar vacío sin que sea un error de sintaxis.

ORDER BY: el orden es parte de la respuesta

-- Primero las urgentes; dentro de cada prioridad, las más antiguas
SELECT id_solicitud, id_hospital, prioridad, fecha_solicitud, estado
FROM solicitudes
WHERE estado IN ('pendiente', 'parcial')
ORDER BY FIELD(prioridad, 'urgente', 'programada'), fecha_solicitud ASC;

FIELD fija el orden que queremos. No uses ORDER BY prioridad DESC a ciegas: las columnas ENUM se ordenan por su posición interna, no por el texto, y el resultado puede ser el contrario del esperado.

ASC es ascendente y es el valor por defecto; DESC invierte. Puedes ordenar por varias columnas y por expresiones. El orden solo es estable si incluyes un criterio que desempate, como id_solicitud.

-- Orden determinista para paginar
SELECT id_unidad, codigo_barras, fecha_vencimiento
FROM unidades_sangre
WHERE estado = 'disponible'
ORDER BY fecha_vencimiento ASC, id_unidad ASC
LIMIT 2 OFFSET 2;

LIMIT 2 OFFSET 2 salta dos filas y devuelve las dos siguientes: la página 2 de un tamaño de página 2. Sin un ORDER BY completo, la página 2 puede repetir o perder filas entre ejecuciones.

Funciones sobre columnas indexadas

WHERE YEAR(fecha_vencimiento) = 2026 obliga a calcular la función en cada fila y suele impedir el uso del índice. Prefiere un rango: fecha_vencimiento >= '2026-01-01' AND fecha_vencimiento < '2027-01-01'.

Caso banco de sangre

La consulta más repetida del mostrador es: unidades disponibles de un grupo y Rh, que venzan en los próximos treinta días, ordenadas por vencimiento. Es un WHERE con igualdad, rango y orden; el índice idx_unidades_disponibilidad está pensado exactamente para ella.

SELECT codigo_barras, tipo_componente, fecha_vencimiento
FROM unidades_sangre
WHERE estado = 'disponible'
  AND grupo_abo = 'O'
  AND factor_rh = '+'
  AND fecha_vencimiento BETWEEN CURDATE() AND DATE_ADD(CURDATE(), INTERVAL 30 DAY)
ORDER BY fecha_vencimiento ASC, id_unidad ASC;
