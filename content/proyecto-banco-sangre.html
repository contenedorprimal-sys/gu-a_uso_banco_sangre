El caso y su alcance

El proyecto pide diseñar, construir y administrar una base de datos en MySQL que demuestre las habilidades de DBA del semestre. El dominio elegido es un banco de sangre: registro de donantes, donaciones, unidades derivadas (glóbulos rojos, plasma, plaquetas), pruebas de laboratorio, solicitudes de hospitales, despachos e inventario con trazabilidad.

No es una maqueta: los scripts deben ejecutarse, las consultas deben devolver datos coherentes y la demo debe mostrar el ciclo completo.

Regla del proyecto

Cada unidad del curso deja un artefacto verificable. Si una unidad no tiene script, consulta o evidencia, no está entregada.

Unidad 1 · DBA y arquitectura

  • Motor: MySQL 8 InnoDB. Transacciones ACID, FKs reales, particiones, roles, eventos y respaldo lógico.
  • Roles del equipo: System DBA, Arquitecto de datos y DBA de seguridad.
  • Esquema: 12 tablas relacionadas, una vista, índices y restricciones CHECK.
  • Evidencia: 00_esquema.sql, 01_datos_demo.sql y el diagrama del README.
-- Verificación rápida de la unidad 1
SELECT table_name, table_type
FROM information_schema.tables
WHERE table_schema = 'banco_sangre'
ORDER BY table_type, table_name;

SELECT COUNT(*) AS tablas
FROM information_schema.tables
WHERE table_schema = 'banco_sangre' AND table_type = 'BASE TABLE';

Unidad 2 · Espacios y disponibilidad

  • Estimación: cinco tablas proyectadas a un año, con índices y margen del 30 %.
  • Fragmentación: movimientos_inventario por RANGE anual; ejemplos LIST y HASH.
  • Automatización: cuatro eventos (vencidas, movimientos, Uptime, purga de auditoría).
  • RTO/RPO: 30 min / 15 min, justificados con el impacto de una caída.
  • Evidencia: 02_unidad2_espacio_particiones_eventos.sql.
-- Estimación y tamaño real, en la misma pantalla
SET @filas = 120000;
SET @bytes = 8 + 4 + 2 + 8 + 80 + 255;

SELECT
  ROUND(@filas * @bytes / 1024 / 1024, 2) AS datos_mb,
  ROUND(@filas * @bytes * 1.20 / 1024 / 1024, 2) AS con_indices_mb,
  ROUND(@filas * @bytes * 1.20 * 1.30 / 1024 / 1024, 2) AS con_margen_mb;

SELECT table_name,
       ROUND((data_length + index_length) / 1024 / 1024, 2) AS total_mb
FROM information_schema.tables
WHERE table_schema = 'banco_sangre'
ORDER BY (data_length + index_length) DESC;

Unidad 3 · Monitoreo y seguridad

  • Roles: laboratorio, recepción, auditoría y DBA, con privilegios diferenciados.
  • Monitoreo: Uptime, conexiones, consultas activas, eventos, espacio y consultas caras.
  • Disponibilidad: problema elegido (SPOF) y mitigación documentada.
  • Auditoría: tres triggers sobre unidades_sangre con JSON de antes/después.
  • Evidencia: 03_unidad3_seguridad_monitoreo_auditoria.sql.

Unidad 4 · Respaldo y recuperación

  • Plan: completo diario + binlog cada 15 min + copia externa cifrada.
  • Simulación: borrado controlado y restauración paso a paso.
  • Validación: conteos, huérfanos, triggers/eventos y checksum.
  • Evidencia: 04_unidad4_respaldo_recuperacion.sql y 04_respaldo_incremental.sh.
# Respaldo completo (ejecutar en terminal)
mysqldump --single-transaction --routines --triggers --events \
  --databases banco_sangre > /respaldo/banco_sangre_$(date +%Y%m%d).sql

# Restauración
mysql --user=dba_sangre --password < /respaldo/banco_sangre_20261101.sql

Unidad 5 · Afinación

  • Parámetros: buffer pool, redo log y max_connections.
  • Índice justificado: idx_unidades_o_positivo sobre la consulta crítica.
  • Medición: EXPLAIN y EXPLAIN ANALYZE antes/después, más tiempo.
  • Evidencia: 05_unidad5_afinacion.sql.
EXPLAIN
SELECT id_unidad, codigo_barras, fecha_vencimiento
FROM unidades_sangre
WHERE estado = 'disponible' AND grupo_abo = 'O' AND factor_rh = '+'
ORDER BY fecha_vencimiento ASC;

CREATE INDEX idx_unidades_o_positivo
  ON unidades_sangre (grupo_abo, factor_rh, estado, fecha_vencimiento);

La demo de 15 a 20 minutos

  1. Modelo (2 min): mostrar el diagrama y explicar por qué donación y unidad son tablas distintas.
  2. Ciclo real (3 min): insertar una donación, derivar dos unidades y mostrar el trigger de auditoría.
  3. Espacio (2 min): ejecutar la proyección y contrastarla con information_schema.
  4. Particiones (3 min): mostrar las particiones de movimientos y un EXPLAIN que solo toca una.
  5. Automatización (2 min): ejecutar el evento de Uptime y revisar la bitácora.
  6. Seguridad (2 min): mostrar roles y un intento denegado.
  7. Respaldo (3 min): restaurar en vivo y verificar conteos.
  8. Afinación (3 min): comparar el plan antes/después del índice.

Consejo para la demo

No leas scripts en voz alta. Cuenta una historia: «entra una donación, se derivan dos unidades, una se prueba, un hospital la pide, se despacha, se audita y se respalda». El código es la evidencia, no el guion.
