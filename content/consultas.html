JOIN: cruzar tablas sin perder el hilo

El modelo relacional separa hechos en tablas. Para responder una pregunta real hay que volver a unirlas. Un JOIN combina filas de dos tablas usando una condición.

-- ¿Quién donó y cuándo?
SELECT d.nombre, d.apellido_paterno, do.fecha_donacion, do.estado
FROM donantes d
INNER JOIN donaciones do ON do.id_donante = d.id_donante
ORDER BY do.fecha_donacion DESC;

El alias (d, do) no es obligatorio, pero evita ambigüedades cuando varias tablas tienen columnas con el mismo nombre.

INNER, LEFT y el resto

TipoDevuelveCuándo usarlo

LEFT JOINTodas las de la izquierda; NULL si no hay coincidencia«Donantes que quizá no han donado»
RIGHT JOINTodas las de la derechaPoco usado; se reescribe como LEFT
CROSS JOINProducto cartesianoCasi nunca; cuidado con el tamaño
 
-- Todos los donantes, aunque nunca hayan donado
SELECT d.id_donante, d.nombre, COUNT(do.id_donacion) AS donaciones
FROM donantes d
LEFT JOIN donaciones do ON do.id_donante = d.id_donante
GROUP BY d.id_donante, d.nombre
ORDER BY donaciones DESC;

La trampa del LEFT JOIN con WHERE

Si pones WHERE do.estado = 'apta' después de un LEFT JOIN, conviertes el join en INNER: las filas sin donación tienen NULL y no cumplen la condición. Si quieres conservarlas, mueve la condición al ON.

GROUP BY: resumir para decidir

-- Unidades disponibles por tipo de componente
SELECT tipo_componente, COUNT(*) AS unidades,
       SUM(volumen_ml) AS volumen_total
FROM unidades_sangre
WHERE estado = 'disponible'
GROUP BY tipo_componente
ORDER BY unidades DESC;

-- Donaciones por mes
SELECT DATE_FORMAT(fecha_donacion, '%Y-%m') AS mes,
       COUNT(*) AS donaciones
FROM donaciones
WHERE estado = 'apta'
GROUP BY mes
ORDER BY mes;

Las funciones de agregado son COUNT, SUM, AVG, MIN y MAX. Todo lo que aparezca en el SELECT y no esté agregado debe estar en el GROUP BY (salvo que ONLY_FULL_GROUP_BY esté desactivado, algo que no conviene).

HAVING: filtrar grupos, no filas

-- Hospitales con más de una solicitud
SELECT h.nombre, COUNT(s.id_solicitud) AS solicitudes
FROM hospitales h
INNER JOIN solicitudes s ON s.id_hospital = h.id_hospital
GROUP BY h.id_hospital, h.nombre
HAVING COUNT(s.id_solicitud) > 1
ORDER BY solicitudes DESC;

WHERE actúa antes de agrupar; HAVING después. Si filtras por una columna que no es agregada, probablemente va en WHERE.

Subconsultas: una pregunta dentro de otra

-- Unidades que no tienen prueba de VIH registrada
SELECT u.id_unidad, u.codigo_barras
FROM unidades_sangre u
WHERE NOT EXISTS (
  SELECT 1
  FROM pruebas_laboratorio p
  WHERE p.id_unidad = u.id_unidad
    AND p.tipo_prueba = 'VIH'
);

-- Donantes que han donado más que el promedio
SELECT nombre, apellido_paterno
FROM donantes
WHERE id_donante IN (
  SELECT id_donante
  FROM donaciones
  GROUP BY id_donante
  HAVING COUNT(*) > (
    SELECT AVG(total) FROM (
      SELECT COUNT(*) AS total FROM donaciones GROUP BY id_donante
    ) AS promedios
  )
);

EXISTS suele ser más claro que IN cuando solo importa si existe al menos una fila. Y evita sorpresas con NULL.

Caso banco de sangre

La consulta más usada del mostrador no es un JOIN complejo: es «unidades disponibles del grupo O+ que vencen primero». Está en el capítulo de índices y es la que se usa para medir antes/después en la unidad 5.

-- Reporte de trazabilidad de una unidad
SELECT u.codigo_barras, u.tipo_componente, u.estado,
       do.fecha_donacion,
       h.nombre AS hospital,
       de.fecha_despacho
FROM unidades_sangre u
JOIN donaciones do ON do.id_donacion = u.id_donacion
LEFT JOIN despacho_detalle dd ON dd.id_unidad = u.id_unidad
LEFT JOIN despachos de ON de.id_despacho = dd.id_despacho
LEFT JOIN solicitudes s ON s.id_solicitud = de.id_solicitud
LEFT JOIN hospitales h ON h.id_hospital = s.id_hospital
WHERE u.codigo_barras = 'GR-2026-0001';
