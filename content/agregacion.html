Agregar es responder con números

Una fila cuenta un hecho; un agregado cuenta una historia. SUM(volumen_ml) dice cuánta sangre hay; COUNT(*) dice cuántas unidades; AVG(hemoglobina) dice qué tan apto es un grupo de donaciones.

FunciónQué haceDetalle importante
COUNT(*)Cuenta filasIncluye filas con NULL.
COUNT(columna)Cuenta valores no nulosIgnora NULL.
COUNT(DISTINCT columna)Cuenta valores distintosÚtil para «cuántos hospitales pidieron».
SUMSumaIgnora NULL; no lo confundas con cero.
AVGPromedioTambién ignora NULL.
MIN, MAXMínimo y máximoFuncionan con fechas y texto.
 
-- Inventario disponible en una sola fila
SELECT
  COUNT(*) AS unidades,
  SUM(volumen_ml) AS volumen_total_ml,
  ROUND(AVG(volumen_ml), 2) AS volumen_promedio,
  MIN(fecha_vencimiento) AS primer_vencimiento,
  MAX(fecha_vencimiento) AS ultimo_vencimiento
FROM unidades_sangre
WHERE estado = 'disponible';

GROUP BY: una fila por grupo

Sin GROUP BY, un agregado colapsa todas las filas en una. Con GROUP BY, calcula un agregado por cada grupo.

-- ¿Cuántas unidades disponibles hay de cada componente?
SELECT
  tipo_componente,
  COUNT(*) AS unidades,
  SUM(volumen_ml) AS volumen_total
FROM unidades_sangre
WHERE estado = 'disponible'
GROUP BY tipo_componente
ORDER BY unidades DESC;

La regla es simple: toda columna del SELECT que no esté dentro de un agregado debe aparecer en el GROUP BY. MySQL puede desactivar ONLY_FULL_GROUP_BY, pero hacerlo permite resultados ambiguos, no más flexibilidad.

ONLY_FULL_GROUP_BY

Si el servidor lo tiene activo, una consulta como SELECT nombre, COUNT(*) FROM donantes falla. Es una protección: no hay un nombre único que represente al grupo. Agrupa por id_donante, nombre o elimina la columna.

Agrupar después de unir tablas

-- Donaciones por donante, incluyendo a quien nunca ha donado
SELECT
  d.id_donante,
  CONCAT(d.nombre, ' ', d.apellido_paterno) AS donante,
  COUNT(do.id_donacion) AS donaciones
FROM donantes d
LEFT JOIN donaciones do ON do.id_donante = d.id_donante
GROUP BY d.id_donante, d.nombre, d.apellido_paterno
ORDER BY donaciones DESC, d.id_donante;

COUNT(do.id_donacion) cuenta valores no nulos. En un LEFT JOIN, quien no tiene donaciones recibe NULL y el conteo da cero. Si usaras COUNT(*), contarías la fila del donante aunque no haya donación.

HAVING: filtrar grupos

WHERE filtra filas antes de agrupar. HAVING filtra grupos después de agregar. Si la condición usa un agregado, va en HAVING.

-- Hospitales con dos o más solicitudes
SELECT
  h.id_hospital,
  h.nombre,
  COUNT(s.id_solicitud) AS solicitudes
FROM hospitales h
JOIN solicitudes s ON s.id_hospital = h.id_hospital
GROUP BY h.id_hospital, h.nombre
HAVING COUNT(s.id_solicitud) >= 2
ORDER BY solicitudes DESC;

-- Solo solicitudes de 2026, y luego agrupar
SELECT
  h.nombre,
  COUNT(*) AS solicitudes_2026
FROM hospitales h
JOIN solicitudes s ON s.id_hospital = h.id_hospital
WHERE s.fecha_solicitud >= '2026-01-01'
  AND s.fecha_solicitud < '2027-01-01'
GROUP BY h.id_hospital, h.nombre
HAVING COUNT(*) > 0;

Agregación condicional: varias preguntas, una pasada

En MySQL, una comparación devuelve 1 o 0. Sumar comparaciones cuenta cuántas filas cumplen cada condición.

SELECT
  tipo_componente,
  COUNT(*) AS total,
  SUM(estado = 'disponible') AS disponibles,
  SUM(estado = 'reservada') AS reservadas,
  SUM(estado = 'despachada') AS despachadas,
  SUM(estado = 'vencida') AS vencidas,
  SUM(estado = 'descartada') AS descartadas
FROM unidades_sangre
GROUP BY tipo_componente
ORDER BY total DESC;

La forma portable usa CASE; ambas son útiles y la segunda se lee mejor cuando la condición es compuesta.

SELECT
  tipo_componente,
  SUM(CASE WHEN estado = 'disponible' THEN 1 ELSE 0 END) AS disponibles,
  SUM(CASE WHEN estado = 'disponible' THEN volumen_ml ELSE 0 END) AS ml_disponibles
FROM unidades_sangre
GROUP BY tipo_componente;

WITH ROLLUP: el total al final

SELECT
  tipo_componente,
  grupo_abo,
  COUNT(*) AS unidades
FROM unidades_sangre
GROUP BY tipo_componente, grupo_abo WITH ROLLUP;

WITH ROLLUP agrega filas de subtotal y total. La fila con tipo_componente NULL y grupo_abo NULL es el total general; no es un dato faltante, es una fila generada por el rollup.

Caso banco de sangre

El reporte diario no pide «todas las unidades»: pide cuántas hay por componente y grupo, cuántas vencen esta semana y cuántas están reservadas. Tres agregaciones sobre la misma tabla responden las tres preguntas sin traer el inventario completo a la aplicación.

Práctica

-- 1. Donaciones por estado y tipo de donación
SELECT estado, tipo_donacion, COUNT(*) AS total
FROM donaciones
GROUP BY estado, tipo_donacion
ORDER BY estado, total DESC;

-- 2. Promedio de hemoglobina por estado de donación
SELECT estado, ROUND(AVG(hemoglobina), 2) AS hemoglobina_promedio
FROM donaciones
GROUP BY estado;

-- 3. Componentes con más de dos unidades registradas
SELECT tipo_componente, COUNT(*) AS unidades
FROM unidades_sangre
GROUP BY tipo_componente
HAVING COUNT(*) > 2;
