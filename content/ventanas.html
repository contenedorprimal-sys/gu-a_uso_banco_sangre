Calcular sin perder filas

GROUP BY reduce varias filas a una. Una función de ventana calcula sobre un conjunto de filas relacionadas y deja cada fila en su lugar. Es la diferencia entre «dame el total por hospital» y «dame cada solicitud con el total de su hospital al lado».

SELECT
  id_solicitud,
  id_hospital,
  fecha_solicitud,
  COUNT(*) OVER (PARTITION BY id_hospital) AS solicitudes_del_hospital
FROM solicitudes
ORDER BY id_hospital, fecha_solicitud;

La cláusula OVER define la ventana: PARTITION BY agrupa, ORDER BY ordena dentro del grupo y el frame decide qué filas entran en el cálculo.

Anatomía de una ventana

funcion() OVER (
  PARTITION BY columna   -- divide el resultado en grupos
  ORDER BY columna       -- orden interno del cálculo
  ROWS BETWEEN ... AND ... -- frame opcional
)
FunciónQué devuelveUso típico
ROW_NUMBER()1, 2, 3… sin repetirElegir una fila por grupo

LAG(), LEAD()Valor anterior o siguienteComparar movimientos
SUM() OVERSuma acumulada o por grupoSaldo corrido

ROW_NUMBER: numerar y elegir

-- Orden de vencimiento dentro de cada componente
SELECT
  codigo_barras,
  tipo_componente,
  fecha_vencimiento,
  ROW_NUMBER() OVER (
    PARTITION BY tipo_componente
    ORDER BY fecha_vencimiento ASC, id_unidad ASC
  ) AS orden_vencimiento
FROM unidades_sangre
WHERE estado = 'disponible'
ORDER BY tipo_componente, orden_vencimiento;

Para quedarte con la primera de cada grupo, calcula el número en una CTE y filtra después. No puedes usar una función de ventana directamente en WHERE, porque el filtro ocurre antes de que la ventana se calcule.

WITH ranked AS (
  SELECT
    codigo_barras,
    tipo_componente,
    fecha_vencimiento,
    ROW_NUMBER() OVER (
      PARTITION BY tipo_componente
      ORDER BY fecha_vencimiento ASC
    ) AS rn
  FROM unidades_sangre
  WHERE estado = 'disponible'
)
SELECT codigo_barras, tipo_componente, fecha_vencimiento
FROM ranked
WHERE rn = 1
ORDER BY fecha_vencimiento;

LAG y LEAD: mirar la fila vecina

SELECT
  id_unidad,
  fecha_movimiento,
  tipo_movimiento,
  LAG(tipo_movimiento) OVER (
    PARTITION BY id_unidad
    ORDER BY fecha_movimiento
  ) AS movimiento_anterior,
  LEAD(tipo_movimiento) OVER (
    PARTITION BY id_unidad
    ORDER BY fecha_movimiento
  ) AS movimiento_siguiente
FROM movimientos_inventario
ORDER BY id_unidad, fecha_movimiento;

Acumulados y promedios móviles

-- Entradas acumuladas por unidad a lo largo del tiempo
SELECT
  id_unidad,
  fecha_movimiento,
  tipo_movimiento,
  SUM(CASE WHEN tipo_movimiento = 'entrada' THEN 1 ELSE 0 END) OVER (
    PARTITION BY id_unidad
    ORDER BY fecha_movimiento
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS entradas_acumuladas
FROM movimientos_inventario
ORDER BY id_unidad, fecha_movimiento;

-- Promedio móvil de tres extracciones
SELECT
  id_unidad,
  fecha_extraccion,
  volumen_ml,
  ROUND(AVG(volumen_ml) OVER (
    ORDER BY fecha_extraccion
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
  ), 2) AS promedio_movil_3
FROM unidades_sangre
ORDER BY fecha_extraccion;

Sin ORDER BY dentro de OVER, el acumulado se calcula sobre toda la partición. Con ORDER BY, el frame por defecto es desde el inicio hasta la fila actual. Escríbelo de forma explícita cuando el resultado dependa del frame.

Top N por grupo

-- Las dos unidades de mayor volumen por componente
WITH ranked AS (
  SELECT
    tipo_componente,
    codigo_barras,
    volumen_ml,
    ROW_NUMBER() OVER (
      PARTITION BY tipo_componente
      ORDER BY volumen_ml DESC, id_unidad ASC
    ) AS rn
  FROM unidades_sangre
)
SELECT tipo_componente, codigo_barras, volumen_ml
FROM ranked
WHERE rn <= 2
ORDER BY tipo_componente, rn;

Ventana frente a GROUP BY

Si la pregunta es «¿cuánto hay por componente?», usa GROUP BY. Si es «¿cada unidad y cuánto representa del total de su componente?», usa una ventana. Muchas consultas necesitan las dos cosas en pasos distintos.

Caso banco de sangre

«¿Cuál es la unidad que vence primero de cada componente?» es un ROW_NUMBER por componente. «¿Cuál fue el movimiento anterior de esta unidad?» es un LAG. «¿Cuántas entradas lleva acumuladas?» es un SUM con frame. Tres preguntas de operación, tres ventanas.

Práctica

-- 1. Ranking de solicitudes por antigüedad dentro de cada prioridad
SELECT
  id_solicitud,
  prioridad,
  fecha_solicitud,
  RANK() OVER (PARTITION BY prioridad ORDER BY fecha_solicitud) AS antiguedad
FROM solicitudes;

-- 2. Última prueba registrada por unidad
WITH pruebas AS (
  SELECT
    id_unidad,
    tipo_prueba,
    fecha_prueba,
    ROW_NUMBER() OVER (PARTITION BY id_unidad ORDER BY fecha_prueba DESC) AS rn
  FROM pruebas_laboratorio
)
SELECT id_unidad, tipo_prueba, fecha_prueba
FROM pruebas WHERE rn = 1;

-- 3. Porcentaje del volumen total que aporta cada unidad
SELECT
  codigo_barras,
  volumen_ml,
  ROUND(volumen_ml / SUM(volumen_ml) OVER () * 100, 2) AS pct_total
FROM unidades_sangre
ORDER BY pct_total DESC;
