Varios servidores, un solo sistema

Un clúster es un conjunto de nodos que trabajan coordinados y, de cara a la aplicación, se comportan como un solo sistema. Es la aplicación concreta de la redundancia: si un nodo cae, los demás siguen atendiendo.

No es un respaldo. Un respaldo protege los datos ante una pérdida; un clúster protege la disponibilidad del servicio en tiempo real.

AspectoActivo-pasivoActivo-activo

Para una clínica con datos sensibles y un equipo de TI de tres personas, activo-pasivo suele ser la recomendación: se gana disponibilidad sin exigir un equipo grande para resolver conflictos. Un banco con 10,000 transacciones por segundo probablemente justifique activo-activo.

MySQL InnoDB Cluster

La solución oficial combina tres piezas:

  • Group Replication: mantiene sincronizados los datos entre nodos.
  • MySQL Router: dirige las conexiones al nodo correcto sin que la aplicación sepa cuál es el primario.
  • MySQL Shell: administra el clúster (crear, revisar estado, recuperar).

Failover: el evento, no la arquitectura

El clustering hace posible el failover; el failover es el evento concreto de conmutación cuando un nodo deja de responder. Tiene cuatro pasos:

  1. Detección: Group Replication nota que el PRIMARY dejó de responder o perdió conexión.
  2. Elección: los nodos restantes eligen un nuevo PRIMARY automáticamente.
  3. Redirección: MySQL Router mueve las conexiones de escritura al nuevo PRIMARY.
  4. Recuperación: el nodo caído, al volver, se resincroniza con el estado actual.

Quién gana la elección

El criterio principal es el menor server_uuid entre los nodos elegibles. La elección solo ocurre si hay quorum.

-- Tabla que simula el estado del clúster
CREATE TABLE nodos_grupo (
  nombre      VARCHAR(20) PRIMARY KEY,
  server_uuid VARCHAR(36),
  rol         VARCHAR(10),
  estado      VARCHAR(10)
);

INSERT INTO nodos_grupo VALUES
  ('Servidor A', '7a4e2f10-1111-11ee-aaaa-000000000101', 'PRIMARY',   'CAIDO'),
  ('Servidor B', '3d88c250-2222-11ee-bbbb-000000000102', 'SECONDARY', 'ACTIVO'),
  ('Servidor C', 'b015f630-3333-11ee-cccc-000000000103', 'SECONDARY', 'ACTIVO');

-- Gana el menor server_uuid entre los ACTIVOS
SELECT nombre, server_uuid
FROM nodos_grupo
WHERE estado = 'ACTIVO'
ORDER BY server_uuid ASC
LIMIT 1;

Resultado: Servidor B. Si B también falla, se actualiza su estado y se repite la consulta; queda C.

Quorum: la mayoría manda

La regla es nodos disponibles > total / 2. Sin quorum, el clúster deja de aceptar escrituras para evitar split-brain: dos partes creyendo que son la verdadera.

SET @total_nodos = 7;
SET @nodos_disponibles = 3;

SELECT IF(@nodos_disponibles > @total_nodos / 2,
          'Hay Quorum',
          'No Hay Quorum') AS resultado;
-- 3 no es mayor que 3.5: NO hay quorum

Por eso los clústeres usan número impar de nodos (3, 5, 7). Con 3 nodos y 2 activos hay quorum; con 1 activo, no.

La transacción a medias

Un cliente hace UPDATE + DELETE sin COMMIT y el PRIMARY falla. ¿Se completa en el nuevo PRIMARY?

No

Sin COMMIT, la transacción no se replicó por completo. No puede «continuar» en otro nodo. Al cliente le llega un error de conexión perdida y la aplicación debe reintentar la transacción desde cero.

Esto es atomicidad: todo o nada. El nuevo PRIMARY no conoce una transacción que nunca se confirmó.

MySQL Router

La aplicación siempre se conecta a la misma dirección (el Router). El Router consulta la topología y redirige. Si una conexión se pierde durante el failover, la aplicación recibe un error y, al reintentar, llega al nuevo PRIMARY.

Caso banco de sangre

El banco de sangre no necesita cinco nueves, pero sí necesita que una cirugía no se detenga porque cayó el servidor. Un clúster de tres nodos con activo-pasivo, Router y ensayos trimestrales cubre el RTO de 30 minutos sin exigir un equipo de operaciones enorme.

Errores comunes

  • Configurar un clúster y nunca probar el failover.
  • Usar número par de nodos: el quorum queda ambiguo.
  • Creer que el clúster reemplaza los respaldos.
  • No implementar reintentos en la aplicación.
  • Ignorar la latencia de red entre nodos geográficamente separados.
