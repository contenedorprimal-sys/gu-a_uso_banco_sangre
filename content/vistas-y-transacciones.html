Una vista es una consulta con nombre

Una vista (VIEW) guarda una consulta, no una copia de los datos. Cada vez que la consultas, MySQL ejecuta la definición contra las tablas actuales. Sirve para reutilizar lógica, simplificar joins y exponer solo una parte de la información.

CREATE OR REPLACE VIEW vista_unidades_disponibles AS
SELECT
  u.id_unidad,
  u.codigo_barras,
  u.tipo_componente,
  u.grupo_abo,
  u.factor_rh,
  u.fecha_vencimiento,
  u.ubicacion,
  d.id_donacion,
  d.fecha_donacion
FROM unidades_sangre u
JOIN donaciones d ON d.id_donacion = u.id_donacion
WHERE u.estado = 'disponible';

SELECT * FROM vista_unidades_disponibles
WHERE fecha_vencimiento <= DATE_ADD(CURDATE(), INTERVAL 7 DAY)
ORDER BY fecha_vencimiento;

La vista no almacena filas: si una unidad cambia de estado, la próxima consulta ya no la muestra. Esa es su ventaja y su límite.

Para qué sirve y qué no resuelve

-- Una vista de trazabilidad: una fila por unidad despachada
CREATE OR REPLACE VIEW vista_trazabilidad_despachos AS
SELECT
  u.codigo_barras,
  u.tipo_componente,
  u.grupo_abo,
  u.factor_rh,
  d.fecha_donacion,
  de.fecha_despacho,
  de.destino,
  s.id_solicitud,
  h.nombre AS hospital
FROM unidades_sangre u
JOIN donaciones d ON d.id_donacion = u.id_donacion
JOIN despacho_detalle dd ON dd.id_unidad = u.id_unidad
JOIN despachos de ON de.id_despacho = dd.id_despacho
JOIN solicitudes s ON s.id_solicitud = de.id_solicitud
JOIN hospitales h ON h.id_hospital = s.id_hospital;

Antes de crearla, prueba el SELECT solo. Una vista con un join mal escrito esconde el error detrás de un nombre bonito.

Transacción: todo o nada

Un despacho no es un solo INSERT. Hay que crear la salida, unir las unidades, cambiar su estado y registrar el movimiento. Si el servidor falla a la mitad, la base no puede quedar con un despacho sin unidades o con una unidad marcada como despachada que nunca salió.

START TRANSACTION;

INSERT INTO despachos (id_solicitud, responsable, destino, estado)
VALUES (5, 'Lic. Ana Prado', 'Hospital Ángeles', 'preparando');

SET @id_despacho = LAST_INSERT_ID();

INSERT INTO despacho_detalle (id_despacho, id_unidad)
VALUES (@id_despacho, 9);

UPDATE unidades_sangre
SET estado = 'despachada', ubicacion = 'Hospital Ángeles'
WHERE id_unidad = 9
  AND estado = 'reservada';

-- Si todo salió bien:
COMMIT;

-- Si algo falló:
-- ROLLBACK;

El COMMIT confirma; el ROLLBACK deshace todo lo hecho desde el START TRANSACTION. El WHERE ... AND estado = 'reservada' es una guarda: si la unidad ya no está reservada, el UPDATE afecta cero filas y la aplicación debe detectarlo con ROW_COUNT().

SAVEPOINT: deshacer una parte

START TRANSACTION;

INSERT INTO despachos (id_solicitud, responsable, destino, estado)
VALUES (4, 'Lic. Ana Prado', 'Clínica del Valle', 'preparando');

SET @id_despacho = LAST_INSERT_ID();

SAVEPOINT antes_del_detalle;

INSERT INTO despacho_detalle (id_despacho, id_unidad)
VALUES (@id_despacho, 13);

-- El detalle estaba mal: se deshace solo desde el savepoint
ROLLBACK TO SAVEPOINT antes_del_detalle;

-- El despacho creado antes del savepoint sigue vivo
COMMIT;

ROLLBACK TO SAVEPOINT no termina la transacción; vuelve a un punto intermedio. Para deshacer todo, usa ROLLBACK sin destino.

Transacciones cortas

Una transacción abierta retiene locks. Si incluye llamadas a una API, esperas de usuario o un SELECT largo, bloquea a otras operaciones. Abre, escribe, confirma; deja fuera todo lo que no sea base de datos.

Caso banco de sangre

El despacho es la operación más sensible del caso: si la unidad no cambia de estado, el inventario miente; si se crea el detalle sin descabezar la solicitud, la trazabilidad se rompe. Una transacción convierte cuatro escrituras en un solo hecho verificable.

Práctica

-- 1. Vista de solicitudes pendientes con nombre del hospital
CREATE OR REPLACE VIEW vista_solicitudes_pendientes AS
SELECT s.id_solicitud, h.nombre AS hospital, s.prioridad, s.fecha_solicitud
FROM solicitudes s
JOIN hospitales h ON h.id_hospital = s.id_hospital
WHERE s.estado IN ('pendiente', 'parcial');

-- 2. Transferencia simulada entre dos unidades: reservar y liberar
START TRANSACTION;
UPDATE unidades_sangre SET estado = 'reservada' WHERE id_unidad = 13;
UPDATE unidades_sangre SET estado = 'disponible' WHERE id_unidad = 14;
ROLLBACK;

-- 3. Ver el estado final: nada cambió
SELECT id_unidad, estado FROM unidades_sangre WHERE id_unidad IN (13, 14);
