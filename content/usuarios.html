Cada persona, su cuenta

Compartir el usuario root es la forma más rápida de no saber quién hizo qué. Cada integrante del equipo y cada aplicación deben tener una cuenta propia. Así la auditoría tiene nombre y apellido, y revocar un acceso no afecta a los demás.

-- Crear un usuario solo para el laboratorio
CREATE USER 'lab_user'@'localhost' IDENTIFIED BY 'Lab#2026';

-- Ver sus privilegios iniciales (normalmente USAGE, es decir, ninguno)
SHOW GRANTS FOR 'lab_user'@'localhost';

El formato 'usuario'@'host' importa: localhost, 127.0.0.1 y % son cuentas distintas. Un usuario creado para localhost no puede conectarse desde otra máquina.

Mínimo privilegio

El principio es simple: cada cuenta recibe solo lo que necesita para su función, ni un privilegio más. En el banco de sangre:

PerfilNecesitaNo necesita
LaboratorioLeer unidades, insertar/actualizar pruebasBorrar unidades, cambiar donantes
Recepción de hospitalVer inventario disponible, crear solicitudesVer datos personales, modificar unidades
AuditoríaLeer auditoría y bitácorasEscribir en la operación
DBAAdministrar el esquemaSer usado por la aplicación
 
GRANT SELECT, INSERT, UPDATE ON banco_sangre.pruebas_laboratorio
  TO 'lab_user'@'localhost';

GRANT SELECT ON banco_sangre.v_unidades_disponibles
  TO 'recepcion_user'@'localhost';

GRANT SELECT ON banco_sangre.auditoria_unidades
  TO 'auditor_user'@'localhost';

FLUSH PRIVILEGES;

FLUSH PRIVILEGES no es necesario después de GRANT en MySQL moderno; se usa cuando modificas las tablas de privilegios a mano. No hace daño, pero no es magia.

Roles: privilegios con nombre

Cuando tres personas del laboratorio necesitan lo mismo, no repitas el mismo GRANT tres veces. Crea un rol, asígnale privilegios y dáselo a los usuarios.

CREATE ROLE rol_laboratorio;

GRANT SELECT, INSERT, UPDATE ON banco_sangre.pruebas_laboratorio TO rol_laboratorio;
GRANT SELECT, UPDATE ON banco_sangre.unidades_sangre TO rol_laboratorio;
GRANT SELECT ON banco_sangre.v_unidades_disponibles TO rol_laboratorio;

GRANT rol_laboratorio TO 'lab_user'@'localhost';
SET DEFAULT ROLE ALL TO 'lab_user'@'localhost';

Si mañana el laboratorio necesita leer donaciones, agregas el privilegio al rol y todos los usuarios lo heredan. Revocar también es centralizado.

Error común

Dar ALL PRIVILEGES ON *.* «para que funcione». Eso convierte cualquier error de la aplicación en un borrado de la base completa. Si una consulta falla por permisos, se corrige el permiso puntual, no se abre todo.

Privilegios por columna y por vista

A veces no quieres ocultar la tabla completa, solo una columna. MySQL permite otorgar SELECT sobre columnas específicas.

-- Recepción puede ver el nombre del donante, pero no su correo ni teléfono
GRANT SELECT (id_donante, nombre, apellido_paterno, tipo_sangre, factor_rh)
  ON banco_sangre.donantes TO 'recepcion_user'@'localhost';

La otra estrategia es una vista que exponga solo lo necesario. El proyecto usa v_unidades_disponibles, que no incluye ningún dato personal del donante.

Revocar y verificar

-- Quitar un privilegio que ya no corresponde
REVOKE INSERT ON banco_sangre.solicitudes FROM 'recepcion_user'@'localhost';

-- Ver todos los privilegios efectivos
SHOW GRANTS FOR 'recepcion_user'@'localhost';

-- Ver los usuarios existentes
SELECT user, host FROM mysql.user ORDER BY user;

En una auditoría, SHOW GRANTS es la primera consulta. Si no puedes explicar por qué cada usuario tiene cada privilegio, hay un problema.

Contraseñas y conexión

  • No escribas contraseñas en scripts versionados. Usa variables de entorno o un archivo de configuración protegido.
  • Rota contraseñas y elimina cuentas de exempleados o proyectos terminados.
  • La aplicación no debe conectarse como root.
  • Si el servidor escucha en red, restringe el host de cada cuenta.
-- Una cuenta de aplicación con lo mínimo
CREATE USER 'app_banco'@'10.0.0.%' IDENTIFIED BY 'App#2026';
GRANT SELECT, INSERT, UPDATE ON banco_sangre.unidades_sangre TO 'app_banco'@'10.0.0.%';
GRANT SELECT, INSERT ON banco_sangre.movimientos_inventario TO 'app_banco'@'10.0.0.%';

Comprobación

-- ¿Qué roles existen?
SELECT role_name, role_host FROM mysql.roles_mapping;

-- ¿Qué privilegios tiene el rol de laboratorio?
SHOW GRANTS FOR rol_laboratorio;

-- Probar una conexión con otro usuario desde terminal:
-- mysql -u lab_user -p -h 127.0.0.1 banco_sangre

La prueba real no es leer el GRANT: es conectarse con ese usuario e intentar la operación prohibida. Si falla con «denied», el privilegio está bien aplicado.
