La pregunta antes que la sintaxis

Una consulta empieza por una pregunta, no por SELECT. En el Banco de Sangre la pregunta puede ser «¿qué unidades O+ están disponibles?» o «¿cuántas donaciones hubo en octubre?». La sintaxis solo traduce esa pregunta a columnas, filas y filtros.

USE banco_sangre;

-- Explorar: primero mira qué hay
SELECT * FROM unidades_sangre LIMIT 5;

-- Responder: pide solo lo necesario
SELECT codigo_barras, tipo_componente, fecha_vencimiento
FROM unidades_sangre
WHERE estado = 'disponible'
ORDER BY fecha_vencimiento;

SELECT * devuelve todas las columnas. Sirve para descubrir una tabla, pero no para una consulta que se ejecutará miles de veces: transporta datos que nadie va a leer.

Proyección: elegir columnas y calcular

La lista entre SELECT y FROM se llama proyección. Puede contener columnas, expresiones y alias.

SELECT
  id_unidad,
  codigo_barras,
  volumen_ml,
  ROUND(volumen_ml / 1000.0, 2) AS volumen_litros
FROM unidades_sangre;

El alias volumen_litros no modifica la tabla: solo nombra la columna del resultado. Si la expresión es delicada, entrecomilla el alias con comillas invertidas.

SELECT
  d.nombre,
  d.apellido_paterno,
  d.apellido_materno,
  CONCAT(d.nombre, ' ', d.apellido_paterno) AS donante,
  d.tipo_sangre,
  d.factor_rh
FROM donantes d
ORDER BY d.apellido_paterno, d.nombre;

DISTINCT: quitar repetidos

DISTINCT elimina filas cuyo resultado completo es idéntico. No elimina «casi iguales» ni elige una fila representante.

-- Combinaciones de grupo y Rh presentes en el inventario
SELECT DISTINCT grupo_abo, factor_rh
FROM unidades_sangre
ORDER BY grupo_abo, factor_rh;

-- Ojo: son dos columnas, no una
SELECT DISTINCT grupo_abo
FROM unidades_sangre;

LIMIT: una muestra, no una respuesta

-- Las cinco unidades que vencen primero
SELECT codigo_barras, tipo_componente, fecha_vencimiento
FROM unidades_sangre
WHERE estado = 'disponible'
ORDER BY fecha_vencimiento ASC
LIMIT 5;

LIMIT recorta el resultado. Sin ORDER BY, el motor puede devolver cualquier subconjunto: el orden de las filas no está garantizado. La paginación completa —LIMIT n OFFSET m— se explica en el capítulo siguiente.

El orden en que MySQL piensa

PasoCláusulaQué ocurre
1FROMSe eligen las tablas y se resuelven los JOIN.
2WHERESe filtran filas.
3GROUP BYSe forman grupos.
4HAVINGSe filtran grupos.
5SELECTSe calculan columnas y alias.
6ORDER BYSe ordena el resultado.
7LIMITSe recorta.

Por eso un alias definido en SELECT no existe todavía en WHERE. En ORDER BY sí puedes usarlo porque ya se proyectó.

-- Falla: el alias aún no existe en WHERE
SELECT volumen_ml, volumen_ml / 1000.0 AS litros
FROM unidades_sangre
WHERE litros > 0.25;

-- Funciona: repite la expresión o filtra en el HAVING de una agregación
SELECT volumen_ml, volumen_ml / 1000.0 AS litros
FROM unidades_sangre
WHERE volumen_ml > 250;

SELECT * en producción

Una consulta con SELECT * se rompe cuando alguien agrega una columna, transfiere más datos de los necesarios y dificulta usar un índice de cobertura. Úsalo para explorar, no como contrato de una aplicación.

Caso banco de sangre

El mostrador no necesita todas las columnas de unidades_sangre: necesita código, componente, grupo, Rh y vencimiento. Pedir solo eso reduce el tráfico y permite que el índice de disponibilidad cubra la consulta.

Práctica

-- 1. Diez donantes activos, solo nombre y grupo
SELECT nombre, apellido_paterno, tipo_sangre, factor_rh
FROM donantes
WHERE activo = 1
ORDER BY apellido_paterno
LIMIT 10;

-- 2. Componentes distintos que existen en el inventario
SELECT DISTINCT tipo_componente FROM unidades_sangre;

-- 3. Código y volumen en litros de las unidades despachadas
SELECT codigo_barras, ROUND(volumen_ml / 1000.0, 2) AS litros
FROM unidades_sangre
WHERE estado = 'despachada';
