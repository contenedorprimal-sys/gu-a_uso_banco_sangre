Una pregunta dentro de otra

Una subconsulta es un SELECT que alimenta a otro. Sirve para comparar contra un conjunto, comprobar si existe algo o construir una tabla intermedia. La clave no es anidar por deporte: es dividir una pregunta grande en preguntas que sí sabes responder.

-- Unidades que no tienen prueba de VIH registrada
SELECT u.id_unidad, u.codigo_barras
FROM unidades_sangre u
WHERE NOT EXISTS (
  SELECT 1
  FROM pruebas_laboratorio p
  WHERE p.id_unidad = u.id_unidad
    AND p.tipo_prueba = 'VIH'
);

EXISTS no devuelve datos: devuelve verdadero o falso. El SELECT 1 es una convención; lo importante es que la subconsulta pueda encontrar al menos una fila.

Escalar: un solo valor

-- Unidades con volumen superior al promedio
SELECT codigo_barras, volumen_ml
FROM unidades_sangre
WHERE volumen_ml > (
  SELECT AVG(volumen_ml)
  FROM unidades_sangre
)
ORDER BY volumen_ml DESC;

La subconsulta escalar debe devolver exactamente una fila y una columna. Si devuelve dos filas, MySQL lanza un error; si devuelve cero, el resultado es NULL y la comparación no selecciona nada.

IN y NOT IN: listas calculadas

-- Hospitales que tienen solicitudes pendientes
SELECT id_hospital, nombre
FROM hospitales
WHERE id_hospital IN (
  SELECT id_hospital
  FROM solicitudes
  WHERE estado = 'pendiente'
);

La trampa de NOT IN con NULL

Si la subconsulta devuelve un NULL, NOT IN puede no devolver ninguna fila, porque x <> NULL es NULL, no verdadero. Usa NOT EXISTS o añade WHERE columna IS NOT NULL dentro de la subconsulta.

CTE: ponerle nombre a un paso

Una Common Table Expression empieza con WITH. Es una consulta con nombre que vive durante la consulta principal. No crea una tabla permanente.

WITH unidades_por_componente AS (
  SELECT
    tipo_componente,
    COUNT(*) AS unidades,
    SUM(volumen_ml) AS volumen_total
  FROM unidades_sangre
  WHERE estado = 'disponible'
  GROUP BY tipo_componente
)
SELECT tipo_componente, unidades, volumen_total
FROM unidades_por_componente
WHERE unidades > 0
ORDER BY volumen_total DESC;

La ventaja aparece cuando necesitas reutilizar el mismo resultado o cuando la consulta tiene varios pasos. Una CTE no acelera por sí sola: es una forma de escribir, no un índice.

Varias CTEs: un pipeline legible

WITH
compras AS (
  SELECT id_hospital, COUNT(*) AS solicitudes
  FROM solicitudes
  WHERE estado IN ('pendiente', 'parcial')
  GROUP BY id_hospital
),
ultimo_despacho AS (
  SELECT id_solicitud, MAX(fecha_despacho) AS fecha
  FROM despachos
  GROUP BY id_solicitud
)
SELECT
  h.nombre,
  c.solicitudes,
  COUNT(d.id_despacho) AS despachos,
  MAX(ud.fecha) AS ultimo_despacho
FROM hospitales h
JOIN compras c ON c.id_hospital = h.id_hospital
LEFT JOIN solicitudes s ON s.id_hospital = h.id_hospital
LEFT JOIN despachos d ON d.id_solicitud = s.id_solicitud
LEFT JOIN ultimo_despacho ud ON ud.id_solicitud = s.id_solicitud
GROUP BY h.id_hospital, h.nombre, c.solicitudes
ORDER BY c.solicitudes DESC;

CTE recursiva: generar una secuencia

-- Un calendario de diez días para un reporte diario
WITH RECURSIVE calendario(fecha) AS (
  SELECT DATE('2026-10-01')
  UNION ALL
  SELECT DATE_ADD(fecha, INTERVAL 1 DAY)
  FROM calendario
  WHERE fecha < '2026-10-10'
)
SELECT c.fecha, COUNT(d.id_despacho) AS despachos
FROM calendario c
LEFT JOIN despachos d
  ON DATE(d.fecha_despacho) = c.fecha
GROUP BY c.fecha
ORDER BY c.fecha;

La parte no recursiva crea la primera fila; la recursiva se repite hasta que la condición deja de cumplirse. Sin un límite, una CTE recursiva puede consumir todos los recursos. MySQL corta por cte_max_recursion_depth.

Caso banco de sangre

La trazabilidad de una unidad se lee mejor como pipeline: donación → unidad → pruebas → despacho → hospital. Una CTE por etapa permite revisar cada paso por separado y detectar en cuál falta información.

Práctica

-- 1. Donantes que nunca han donado
SELECT d.id_donante, d.nombre, d.apellido_paterno
FROM donantes d
WHERE NOT EXISTS (
  SELECT 1 FROM donaciones do WHERE do.id_donante = d.id_donante
);

-- 2. Unidades con resultado positivo en alguna prueba
SELECT u.codigo_barras, p.tipo_prueba, p.resultado
FROM unidades_sangre u
JOIN pruebas_laboratorio p ON p.id_unidad = u.id_unidad
WHERE p.resultado = 'positivo';

-- 3. Top de componentes por volumen disponible, con CTE
WITH volumen AS (
  SELECT tipo_componente, SUM(volumen_ml) AS ml
  FROM unidades_sangre
  WHERE estado = 'disponible'
  GROUP BY tipo_componente
)
SELECT * FROM volumen ORDER BY ml DESC;
