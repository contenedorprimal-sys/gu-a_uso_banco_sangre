INSERT: registrar un hecho

Un INSERT agrega filas. Lo importante no es la sintaxis, sino que la fila represente un hecho real y completo. Si falta la fecha o el estado, la base queda con datos que después nadie puede interpretar.

USE banco_sangre;

INSERT INTO donantes
  (nombre, apellido_paterno, apellido_materno, fecha_nacimiento,
   sexo, tipo_sangre, factor_rh, telefono, correo)
VALUES
  ('Ana Sofía', 'Ramírez', 'López', '1992-04-18',
   'F', 'O', '+', '5512345601', 'ana.ramirez@example.com');

-- Varias filas en una sola sentencia
INSERT INTO hospitales (nombre, contacto, telefono, convenio)
VALUES
  ('Hospital General de Zona', 'Dra. Patria Solís', '5555001100', 'activo'),
  ('Hospital Ángeles',         'Dr. Mario Lara',    '5555002200', 'activo');

El id no se envía: AUTO_INCREMENT lo genera. Si necesitas el valor recién creado, usa LAST_INSERT_ID() en la misma conexión.

INSERT INTO donaciones (id_donante, fecha_donacion, estado)
VALUES (LAST_INSERT_ID(), NOW(), 'registrada');

SELECT: leer con preguntas concretas

SELECT * sirve para explorar, no para una aplicación. En producción pide solo las columnas que necesitas: menos datos, menos red, menos memoria.

-- Explorar
SELECT * FROM donantes LIMIT 5;

-- Columnas concretas, con filtro y orden
SELECT id_donante, nombre, apellido_paterno, tipo_sangre, factor_rh
FROM donantes
WHERE activo = 1 AND tipo_sangre = 'O'
ORDER BY apellido_paterno, nombre;

-- Buscar un patrón
SELECT nombre, correo
FROM donantes
WHERE nombre LIKE 'Ana%';

-- Valores nulos
SELECT nombre, correo
FROM donantes
WHERE correo IS NULL;

NULL no es cero ni cadena vacía: es ausencia de dato. Por eso se compara con IS NULL, nunca con = NULL.

UPDATE: el WHERE es la diferencia entre corregir y destruir

-- Cambiar el estado de UNA unidad
UPDATE unidades_sangre
SET estado = 'reservada', ubicacion = 'Refrigerador 1'
WHERE id_unidad = 9;

-- Subir el precio de una categoría (varias filas)
UPDATE productos
SET precio_unitario = ROUND(precio_unitario * 1.08, 2)
WHERE categoria = 'Electrónica';

Antes de ejecutar un UPDATE

Ejecuta el mismo WHERE con SELECT COUNT(*). Si el número no es el que esperas, detente. Un UPDATE sin WHERE actualiza todas las filas y no hay botón de deshacer fuera de una transacción.

-- Verificar el alcance antes de tocar
SELECT COUNT(*) AS filas_afectadas
FROM unidades_sangre
WHERE estado = 'disponible' AND fecha_vencimiento < CURRENT_DATE;

DELETE: borrar es una decisión de negocio

-- Borrar un registro puntual
DELETE FROM solicitud_detalle
WHERE id_detalle = 10;

-- Borrar solicitudes canceladas de un año (con cuidado)
DELETE FROM solicitudes
WHERE estado = 'cancelada'
  AND fecha_solicitud < '2025-01-01';

En un banco de sangre casi nada se borra: se marca como descartada, vencida o cancelada. El borrado físico destruye trazabilidad. Si de verdad hay que borrar, primero respalda y documenta.

Varias operaciones, un solo hecho

Registrar un despacho implica crear el despacho, unir las unidades y cambiar su estado. Si falla a la mitad, la base quedaría inconsistente. Una transacción agrupa todo o nada.

START TRANSACTION;

INSERT INTO despachos (id_solicitud, responsable, destino, estado)
VALUES (3, 'Lic. Ana Prado', 'Hospital General de Zona', 'en_transito');

SET @id_despacho = LAST_INSERT_ID();

INSERT INTO despacho_detalle (id_despacho, id_unidad) VALUES (@id_despacho, 9);

UPDATE unidades_sangre
SET estado = 'despachada'
WHERE id_unidad = 9;

-- Si todo está bien:
COMMIT;

-- Si algo salió mal:
-- ROLLBACK;

Caso banco de sangre

La unidad 9 estaba reservada. Al despacharla, el trigger de auditoría guarda el estado anterior y el nuevo. Si el COMMIT falla, la unidad sigue reservada y no existe un despacho huérfano.

LIMIT y ORDER BY no son decoración

-- Las cinco unidades que vencen primero
SELECT codigo_barras, tipo_componente, fecha_vencimiento
FROM unidades_sangre
WHERE estado = 'disponible'
ORDER BY fecha_vencimiento ASC
LIMIT 5;

Sin ORDER BY, el orden de las filas no está garantizado. Aunque hoy salga «bonito», mañana el optimizador puede cambiarlo.
